## 7. Why this exact shape

### CI split: API job + web job, no Docker

`.github/workflows/ci.yml`:

| Job | Runner defaults | Steps |
|---|---|---|
| `api` | `apps/api`, Python 3.12, pip cache on `requirements.txt` | `pip install -r requirements.txt` → `python -m compileall -q .` → `pytest` |
| `web` | `apps/web`, Node 22, npm cache on lockfile | `npm ci` → `npm run build` with `NEXT_PUBLIC_API_URL=http://localhost:8000` |

`compileall` is the “lint-ish” stand-in named in the workflow (`name: Lint-ish (compileall)`). No ruff/eslint gate was in the plan file map. Docker stays out so PRs do not depend on compose/engine flakes; the show gate remains `docker compose up --build` locally (`README.md:98-100`).

Branch filter `feat/**` matches this worktree branch name pattern so the feature branch is covered before merge to `main`.

### Smoke uses fixture, not live research luck

`scripts/demo_walk.py` docstring (`:7-8`): does not require Docker, Gemini, or IMAGE_GEN; uses unofficial Neutrogena fixture so empty `GEMINI_API_KEY` still walks.

Sequence:

1. `GET /health` — miss → SKIP 0
2. `POST /radar/fetch` — prove Fetch exists; HTTP/network fail → warn, continue
3. `POST /radar/fixture` — labeled fixture report (Task 11 bridge)
4. `POST /factory/run` with that `report_id`
5. `GET /drafts/{id}/image` must start with PNG magic `\x89PNG`
6. `POST /review/{id}` approve with named user `demo_walk` + non-empty reason
7. `GET /export/{id}` must start with ZIP magic `PK`

That mirrors the stranger walk without depending on GDELT/Reddit LAN luck (same friction Tasks 3/11 already recorded).
